# Проверка реализации

Дата: 2026-10-10 (Asia/Yakutsk). Rust/Cargo 1.99.0, без Rust-зависимостей.
Согласованная граница тестов: **только реальный CLI-процесс**.

| Платформа | Фактическая среда | Debug | Release |
|---|---|---|---|
| Linux x86_64 | Ubuntu 24.04.4 LTS в WSL, нативный ELF x86_64, gcc-13 | 26/26 | 26/26 |
| Win32 x86 | Windows NT 10.0.22631 x64, PE32 x86 под WOW64, MSVC | 25/25 + отдельная проверка UTF-16 | 26/26 |

Release-набор проверяет окончательные оптимизированные бинарники. Native CLI
процессы не вызывают Rozm.exe, Python, Wine, LAME или аудиоустройство.
Linux-зависимости по ldd: libc.so.6, libgcc_s.so.1 и системный ELF loader.
Win32 имеет консольную подсистему и статический CRT; PE imports содержат только
api-ms-win-core-synch-l1-2-0.dll, bcryptprimitives.dll, KERNEL32.dll, ntdll.dll.
Полноценная 32-битная Windows и исторические Windows XP/7 отдельно не проверялись.

## RED → GREEN

Поведение добавлялось вертикальными срезами: новый тест CLI → наблюдаемая
ошибка → минимальная реализация → успешный повтор теста. Среди зафиксированных
циклов:

| CLI-сценарий | RED | GREEN |
|---|---|---|
| Создание WAV и словарное произношение | Каркас не синтезировал; WAV расходился с оригиналом | Нативная загрузка, фонетика и PCM совпали с эталоном |
| Числа и Latin fallback | Отличие от исходных PCM | Восстановлены таблицы и транслитерация |
| `2+3=5` и `А.` | Несовпадение исходных WAV | Раскрытие символов и имён букв |
| `.mp3` как выход | Создавался WAV под неверным расширением | Отказ до записи |
| Длинный аргумент | CLI начинал читать ресурсы | Проверка 32768 UTF-8 байт до загрузки |
| `wif` с count = u32::MAX | Паника переполнения на Win32 | Проверяемое сложение и явная ошибка |
| Голосовой ресурс >32 MiB | Ресурс принимался | Отказ до чтения банка |
| PCM >64 MiB | Создавался чрезмерный WAV | Ограничение буферов и сохранение прежнего файла |
| Только `#1#2#3` | Создавался WAV без речи | Ошибка и сохранение прежнего файла |

Регрессии кавычек, апострофов, LF/CRLF/CR, буквального `\n`, директив, путей,
ошибок вывода, отсутствующих/повреждённых ресурсов проходят через прямой argv.
Текст не интерпретируется как команда. Каждый запуск имеет дедлайн 30 секунд.
Тестов внутренних функций или публичного Rust API нет.

## Независимые эталоны и shell

Все 20 WAV-эталонов повторно воспроизведены и сверены инструментом
`python tools/regenerate-fixtures.py`, исполняющим оригинальные машинные
процедуры Rozm.exe. Rust-код не участвует в их получении. Эталоны проверяют
конкретный корпус; GUI-экспорт и произвольный текст не объявляются доказанно
эквивалентными. Условия и ограничения harness описаны в tools/README.md.

`scripts/smoke.sh` проходит в Bash Ubuntu с удалёнными DISPLAY/WAYLAND_DISPLAY;
`scripts/smoke.ps1` проходит в Windows PowerShell. Обе проверки передают кавычки
и настоящий перенос строки, затем сравнивают весь PCM с двумя исходными
образцами. Они используют готовые комплекты и не задают ROZM_DATA_DIR.

Release WAV для «Привіт, світе!» на Linux, Win32 и оригинальном эталоне:

```text
SHA-256: 0001E456DA03E366E047884741680952294BE26E38E6836FF42ED2B40B209C89
PCM: 20430 bytes, mono 11025 Hz unsigned 8-bit
```

`cargo fmt --check`, `cargo clippy --offline --all-targets -- -D warnings`,
Clippy для i686-pc-windows-msvc и `git diff --check` проходят.
Локальные журналы release-тестов: target/validation-ubuntu-release.log и
target/validation-win32-release.log (исключены из Git).

Сохраняемые особенности: скорость только голоса 1; исходная нормализация
пропускает ґ/Ґ; English dictionary отсутствует, применяется Latin fallback;
WAV повторяет исходный unpadded layout последнего data chunk.
